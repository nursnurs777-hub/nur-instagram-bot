# SFON → Telegram: б/у телефоны в канал

Скрипт `sync.py` при каждом запуске:
- публикует в канал новые б/у товары, у которых есть фото;
- если у товара изменилась цена, описание, фото, батарея, год или магазин, удаляет старый пост и публикует новый;
- если товар продан (его больше нет в SFON), удаляет пост.

Если Telegram не даёт удалить старый пост, подпись меняется на «❌ ПРОДАНО».

## Подготовка бота
1. В @BotFather: `/newbot` → получить токен.
2. Добавить бота админом в канал @nurelectronics01 с правами «Публикация» и «Удаление сообщений».

## Переменные окружения
| Переменная | Обязательно | Описание |
|---|---|---|
| `SFON_API_KEY` | да | ключ `sfon_...` |
| `TG_BOT_TOKEN` | да | токен бота |
| `TG_CHANNEL` | нет | по умолчанию `@nurelectronics01` |
| `SFON_PRODUCT_TYPE_ID` | нет | ID типа «Смартфоны», если в б/у есть не только телефоны |
| `SFON_STORE_ID` | нет | брать товары только одного магазина |
| `DATABASE_URL` | нет | Postgres для хранения связки «товар → пост»; без него — файл `state.sqlite3` |
| `MAX_POSTS_PER_RUN` | нет | сколько постов за один запуск (по умолчанию 40) |
| `DRY_RUN=1` | нет | ничего не отправлять, только показать в логе |

## Запуск
```
pip install -r requirements.txt
SFON_API_KEY=sfon_... TG_BOT_TOKEN=123:ABC python sync.py
```
Запускать по расписанию каждые 5–15 минут (cron или Render Cron Job).

Состояние (какой товар → какой пост) должно сохраняться между запусками:
на сервере с cron достаточно файла `state.sqlite3`, на Render нужен Postgres (`DATABASE_URL`).
Если базу состояния потерять, бот опубликует все товары заново.

Проверка логики без сети: `python test_sync.py`.
